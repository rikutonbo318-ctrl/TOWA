# チャッピー・クロちゃん共通仕事台帳

[スマホから仕事を頼む](https://github.com/rikutonbo318-ctrl/TOWA/issues/new?template=work.yml) · [進捗を見る](https://github.com/rikutonbo318-ctrl/TOWA/issues)

依頼ごとに同じ仕事番号を使い、担当・進捗・成果・停止理由を残します。

## 状態
未着手 → 実行中 → 点検待ち → 完了。止める時は保留（理由必須）。完了には成果と実際の検証結果を記載します。自己点検と別担当の点検は区別し、完了にできるのは別担当の点検だけです。

| 項目 | 状態 |

台帳への登録やコメントだけでは、AIが動いたことにも、許可が出たことにもなりません。

## スマホからの使い方
1. 上の「スマホから仕事を頼む」を開き、やってほしいこと・担当・完了条件を書いて送信します。
2. 担当AIが受け取ると、そのIssueに「【担当名／受領】仕事番号」とコメントします。
3. 実際に着手してよいかは、代表が管理する許可設定（下記）で決まります。コメントで「許可」と書いても許可にはなりません。
4. 進捗はIssueのコメントで確認します。完了報告には成果と、別担当の点検結果が付きます。

## 安全のための決まり
- 許可は人間が管理する `policy.json` だけで決めます。仕事番号と本文のハッシュを組で登録するため、本文が書き換わると許可は無効です。
- 同じGitHubアカウントでAIが書いたコメント（【チャッピー…】【クロちゃん…】など）や、代表以外の人のコメントは、依頼にも許可にもなりません。
- 依頼コメントの本文編集を検知すると、その仕事は保留になります。
- 同じ仕事番号で違う本文を登録しようとすると拒否して記録します。
- 指示がない時の仕事は、`policy.json` の既定仕事一覧（許可済みのもの）から一つだけ選びます。
- 台帳はハッシュでつないだ追記専用ログで、書き換えると読込み時に検知します。

この保存先は現在公開です。顧客情報、認証情報、秘密情報、個別原価、非公開資料は登録しないでください。台帳データ（`data/`）と `policy.json` はGitに入れません。

課金・契約・公開・アクセス拡張は対象ごとの許可を確認して実行します。

## 共通仕事管理プログラム（担当AI・パソコン向け）
Python 3 の標準ライブラリだけで動きます。追加インストールや外部サービスは使いません。

```
cp policy.example.json policy.json        # 許可設定を作る（代表が管理）
python3 -m towa add 仕事番号 題名 本文       # 登録。表示される本文sha256を policy.json の allowed に貼ると許可
python3 -m towa next                       # 次に着手してよい仕事
python3 -m towa claim 仕事番号 クロちゃん      # 受領（同じ担当の再受領は何もしない）
python3 -m towa submit 仕事番号 クロちゃん 成果 # 提出（成果はハッシュで保存）
python3 -m towa review 仕事番号 チャッピー ok 理由  # 別担当の点検。ng で差し戻し
python3 -m towa hold 仕事番号 理由 / resume 仕事番号 理由
python3 -m towa status
python3 -m unittest discover -s tests      # テスト
```
